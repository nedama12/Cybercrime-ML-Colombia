{% endcall %} {% call fold('Initial user instructions', kicker='5.5') %}
  1. Create an account (name, email and a password with letters and numbers) or log in.
  2. Open Report an incident and answer the three steps: when and where, how it happened, in your own words.
  3. Read the result: type of incident, confidence, first steps and official channels. Answer "Does this describe what happened to you?".
  4. Follow the status in Dashboard → My reports. Analysts use Review to confirm the category and close the case.
{% endcall %} {% call fold('Integration plan with the information system (Activity 2)', kicker='5.6') %}
  • Roles: citizen and analyst already exist; an administrator role will manage users and model versions.
  • Persistent database: move from SQLite to PostgreSQL on Render with the same tables (users, incident_reports, login_attempts).
  • Workflow: received → in review → closed, already implemented; Activity 2 adds case assignment to analysts and a CRUD of categories and first steps.
  • Inference history: each report already stores date, user, prediction, confidence, model version and inference time; it will feed the monitoring dashboard.
  • Model service: src/report_model.py is the single entry point, so a new version only replaces the joblib file and its info JSON.
