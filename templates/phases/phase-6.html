How drift and degradation are detected

  • Data drift: the Population Stability Index compares the distribution of each feature received in production with the training distribution stored in models/reference_stats.json.
  • Performance degradation: predictions are compared with actual outcomes when the analyst closes a case. The live metrics are compared with the test metrics of the deployed version.
  • Signals from users: false positive / false negative reports and incidents.

The rules run on the monitoring dashboard and in the command flask --app app monitoring-report.

Retraining criteria

  • Significant drift (PSI > 0.25) in any of the five most important features for two consecutive weekly reviews.
  • Live F1 more than 0.05 below the test F1, or live recall below 0.90, with at least 30 verdicts.
  • Accumulation of 200 new closed cases with verdict (new labeled data).
  • Repeated false negative reports for the same type of URL.

Risks, quality controls and update procedure

  • Quality controls: automated tests (pytest) for authentication, roles, cases and inference; feature parity check between the app and the dataset; the model is validated on load (features, classes, scikit-learn version).
  • Update procedure: (1) retrain with the original data plus the verdicts of closed cases; (2) evaluate on a new independent test set and compare with the current version; (3) publish only if it improves the selection criterion; (4) increase the version in model_metadata.json, replace the files in models/ and redeploy; (5) keep the previous version for rollback.
  • Risks: concept drift as attackers change techniques; dataset shortcut (legitimate URLs with "www"); excessive trust in the model. Every final decision stays with an analyst.

Initial monitoring test

The command flask --app app seed-demo creates demonstration cases and predictions labeled SIMULATED in every table and page, so the logging and monitoring can be tested before real use. The monitoring dashboard has an option to exclude simulated data, and the operational review can be printed with flask --app app monitoring-report --days 7.
