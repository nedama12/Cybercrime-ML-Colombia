Problem and context

{{ project.problem }}

Law 1273 of 2009 created the Colombian legal framework for cybercrime (articles 269A to 269J). Its article 269G, website spoofing to capture personal data, describes what is commonly known as phishing: a fake link that imitates a bank, a store or a public entity to steal credentials or money. Phishing is usually the first step of other offenses in the same law, such as electronic theft (269I) and non-consensual transfer of assets (269J).

Questions the model answers

  1. Is this URL more likely to be phishing or legitimate?
  2. How confident is the model, and how urgent is the review (risk level)?
  3. Which characteristics of the URL are unusual compared with the legitimate URLs seen in training?

Learning task: supervised binary classification. Target variable is_phishing (1 = phishing, 0 = legitimate).

Data quality, relevance and sufficiency

  • Colombian cybercrime data: 22 rows without location were removed; "SIN DATO" values were converted to missing values; 2026 is flagged as a partial year. The dataset reports aggregated cases, not individual URLs, so it is used as context and not for training.
  • PhiUSIIL: 850 rows share a repeated URL; URLs with contradictory labels were removed and the remaining duplicates were dropped. Classes are reasonably balanced (about 43% phishing after cleaning).
  • Known bias: every legitimate URL in PhiUSIIL starts with https://www. and has URLSimilarityIndex = 100, while only 2.4% of phishing URLs start that way. A model can learn these shortcuts and look perfect in the test set but fail on real links. This risk is carried to Model Engineering (feature selection) and to Monitoring (drift checks).
  • Sufficiency: more than 165,000 training rows give enough examples for the three algorithms considered.

Feasibility, limitations and risks

Technical feasibility

Open data, scikit-learn models that train on a laptop, and a Flask application deployable on Render with a managed PostgreSQL database.

Organizational feasibility

Three team members with separated responsibilities: data engineering, model engineering and application engineering.

Limitations

The model only sees features computed from the URL text. It does not visit the page, so it cannot see the page content and it is not a replacement for a security analyst.

Risks

Dataset shortcuts (see above), concept drift as attackers change techniques, and false negatives that let a phishing link pass. Mitigated with analyst review, outcome tracking and drift monitoring.
