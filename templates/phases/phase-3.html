Algorithms considered and why

The task is supervised binary classification on tabular, mostly numeric features computed from the URL. Three algorithms with different levels of complexity and interpretability were compared:

AlgorithmWhy it fits the problemMain hyperparameters
Logistic RegressionLinear baseline, fast and interpretable (coefficients). Requires scaling, fitted inside the Pipeline on training data only.C (regularization), class_weight
Decision TreeCaptures non-linear rules such as "many digits and an unusual TLD"; easy to explain to analysts; prone to overfitting.max_depth, min_samples_leaf
Random ForestEnsemble of trees that reduces the variance of a single tree; robust to outliers and different scales.n_estimators, max_depth, min_samples_leaf

How domain knowledge informed the decisions

  • Only features that the deployed system can compute from the URL text are used: the server never visits a possibly malicious page.
  • Recall of the phishing class is prioritized: missing a phishing link (false negative) is more costly than an extra manual review.
  • Partitions and cross-validation are grouped by domain, because attackers reuse domains and a random split would overestimate performance.
  • Features that encode dataset artifacts (for example URLSimilarityIndex, equal to 100 for every legitimate URL) are treated with caution, as documented in phase 1.
