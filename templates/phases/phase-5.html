Flask demonstration integrated in the business process

The model is not a standalone form: it is one step of the case management workflow.

  1. A reporter registers a suspicious URL and where it was received.
  2. An analyst classifies the case. The server computes the features, runs the Pipeline and stores the prediction (date, user, probability, result, model version, response time).
  3. The probability becomes a risk level that sets the case priority and a recommended action: high = block and escalate, medium = manual review, low = monitor.
  4. The analyst reviews the case, records the actual outcome (verdict) and the action taken, and closes it. Disagreements with the model require a justification.
  5. Verdicts feed the live performance indicators and the retraining set.

Analysts can also check a URL received outside the system and open a case from the result.

Inputs and outputs

Input

A URL beginning with http:// or https:// (max. 2,048 characters, with a domain). The system derives {{ (meta.features | length) if meta.features else 19 }} numeric features. If the model needs features that cannot be computed from the URL, the analyst is asked to type them and the prediction is flagged.

Output

Phishing probability (0-1), class (phishing / legitimate, threshold {{ '%.2f' % (meta.threshold or 0.5) }}), risk level, recommended action, comparison of the URL features with the training medians, and the model version used.

Dependencies and execution

Python 3.13, Flask 3.1, Flask-SQLAlchemy, Flask-Login, Flask-WTF, scikit-learn 1.9.1, pandas, joblib and gunicorn (exact versions in requirements.txt). PostgreSQL in production, SQLite locally.

Initial user instructions

  • Reporters: create an account, choose "Report a URL", paste the link without opening it and follow the status in "Cases".
  • Analysts: open new cases, press "Classify with the model", read the risk and recommendation, take the case, and close it with your verdict and action.
  • Administrators: assign roles, follow the monitoring dashboard and answer incidents.

The complete user manual and a training guide are in docs/USER_MANUAL.md and docs/TRAINING_GUIDE.md.

Integration plan with the information system

The model is loaded by a service inside the same Flask application (cyberapp/ml/service.py) and used by the case management module. Updating the model means replacing the files in models/ and redeploying; no code changes are needed while the input contract is respected. Each prediction keeps the model version, so results of different versions remain traceable.

Monitoring, incidents and user feedback

  • Monitoring: every request is logged with endpoint, status, response time and user; administrators see the monitoring dashboard (phase 6). /healthz reports database and model status to Render.
  • Incidents: any user can report a problem ("Report a problem"). Server errors are logged with their traceback and shown to the administrator.
  • Feedback on results: from a case, a user can report a false positive or false negative; the administrator answers and the case is added to the retraining review.
