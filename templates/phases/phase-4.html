Evaluation metrics and why

MetricQuestion it answersRole in the decision
Recall (phishing)Of all phishing URLs, how many did the model catch?Main criterion: a missed phishing link reaches users
Precision (phishing)Of the URLs flagged as phishing, how many really are?Controls analyst workload and blocking of legitimate sites
F1-scoreBalance between precision and recallModel selection criterion
AccuracyShare of correct predictionsReference only (classes are ~43/57)
ROC AUCRanking quality independent of the thresholdSupports the choice of the decision threshold

Cross-validation

Cross-validation must respect the structure of the data: URLs of the same domain are not independent, so folds are grouped by domain (for example StratifiedGroupKFold), and it is run only on the training partition. The validation partition is used to compare algorithms and tune hyperparameters; the test partition is used once, at the end.

Overfitting, underfitting, bias and risks

  • Dataset shortcut: in PhiUSIIL every legitimate URL starts with https://www.. A model can reach almost perfect test scores by learning this pattern and then flag real legitimate URLs without "www" (for example https://github.com) as phishing. Test-set scores are therefore an optimistic upper bound; the real performance is measured in operation against analyst verdicts (phase 6).
  • Temporal bias: the dataset is a snapshot (2024). New phishing techniques appear constantly, so drift is monitored.
  • Mitigation: human review of every case, priority by risk level, outcome tracking and retraining criteria.
