About the project

Evidence for analysis, guidance for action.

A research platform for Colombian cybercrime records and practical cybersecurity education.

Problem and justification

Cybercrime records are difficult to interpret and aggregate categories do not explain what an individual should do during an incident. This project explores the available data while making defensive first steps easier to find.

◎
General objective

Analyze cybercrime information in Colombia, examine temporal and territorial patterns, evaluate supported ML tasks, detect suspicious URL patterns, and provide practical prevention and response guidance.

＋
Specific objectives

Explore available records; identify geographic and temporal patterns; evaluate crime-category classification honestly; analyze URL text for phishing indicators; visualize findings; and guide users through common security situations.

Data, methods and architecture

How the platform works.

Flask serves focused modules backed by existing processed data, persisted model pipelines, and a transparent rules engine.

01

Data and methods

Processed Colombian cybercrime process records support descriptive analysis and an experimental category classifier. A separate UCI PhiUSIIL dataset supports URL-text phishing model training. Territorial views use processed report-year rates where matched. The workflow is CRISP-ML(Q)-inspired: problem/data understanding, preparation, model development, evaluation, and deployment; ongoing monitoring and formal governance remain future work.

02

Technologies

Python, Flask, pandas, scikit-learn, SQLite, joblib, and Matplotlib power the web application, analysis, persisted models, account history, and plots.

03

System architecture and workflow

Browser form → Flask route → existing ML pipeline or rule-based guidance engine → rendered result. The assistant uses no external AI service and does not persist a situation description.

04

Limitations and interpretation

The cybercrime classifier has low macro F1 (legacy test score about 0.118) because aggregate fields lack conduct details. Its labels are not legal conclusions. Territorial counts are recorded processes, not prevalence; forecasts are exploratory. URL scores cannot inspect site content.
